Instalando o Git

Baixe o instalador em git-scm.com/downloads/win ou instale pelo terminal (PowerShell):

winget install --id Git.Git -e --source winget

O instalador faz muitas perguntas. Pode deixar o padrão em quase todas, com três ajustes:

  1. Choosing the default editor: escolha Visual Studio Code (se não escolher, o padrão é o Vim, que confunde quem nunca usou).
  2. Adjusting the name of the initial branch: marque Override e deixe main.
  3. Adjusting your PATH: deixe Git from the command line and also from 3rd-party software.

O instalador traz o Git Bash, um terminal que aceita os mesmos comandos do macOS e do Linux. Os exemplos deste guia funcionam nele.

Abra o Terminal e digite:

git --version

Se o Git não estiver instalado, o macOS oferece instalar as Command Line Tools. Aceite e espere terminar. Se usa Homebrew, a alternativa é:

brew install git

Use o gerenciador de pacotes da sua distribuição:

# Ubuntu, Debian, Mint
sudo apt update && sudo apt install git

# Fedora
sudo dnf install git

# Arch
sudo pacman -S git

Depois, feche e abra o terminal de novo e confira:

git --version
git version 2.51.0

Qualquer versão a partir da 2.28 serve. Se aparecer “comando não encontrado”, veja o que fazer.

Configuração inicial

Faça uma vez em cada computador. O --global vale para todos os repositórios do seu usuário.

# quem é você (aparece em cada commit)
git config --global user.name "Seu Nome"
git config --global user.email "seu-email@exemplo.com"

# a branch principal de projetos novos se chama main
git config --global init.defaultBranch main

# usar o VS Code para escrever mensagens (em vez do Vim)
git config --global core.editor "code --wait"

# git pull junta as versões com merge (evita um aviso comum)
git config --global pull.rebase false

# conferir tudo
git config --global --list

No Windows, inclua também esta linha. Ela converte as quebras de linha automaticamente e evita diferenças falsas quando colegas usam macOS ou Linux:

git config --global core.autocrlf true
git config --global core.autocrlf input
git config --global core.autocrlf input

Nome e e-mail não são login

Essa configuração só carimba seus commits. Ela não conecta você ao GitHub. Use o mesmo e-mail da sua conta do GitHub para que os commits apareçam no seu perfil. Se não quiser expor o e-mail, use o endereço …@users.noreply.github.com que aparece em GitHub → Settings → Emails.

Criando a conta no GitHub

  • Escolha um nome de usuário que você usaria num currículo: ele vira o endereço do seu perfil (github.com/seu-usuario).
  • Ative a autenticação em dois fatores (2FA) em Settings → Password and authentication. O GitHub exige isso de quem contribui com código.
  • Sendo estudante, peça o GitHub Student Developer Pack com seu e-mail institucional. Ele libera o GitHub Copilot, o GitHub Pro e ferramentas de parceiros sem custo.

Conectando o computador ao GitHub

Para baixar um repositório público, não precisa de login. Para enviar (push), o GitHub precisa saber quem é você. Escolha um caminho:

No Windows, o Git já vem com o Git Credential Manager. No primeiro git push, abre uma janela do navegador: faça login no GitHub e autorize. Pronto, fica salvo.

No macOS e no Linux, o caminho mais simples é o GitHub CLI:

gh auth login
# responda: GitHub.com → HTTPS → Yes (autenticar o Git) → Login with a web browser

Mais técnico, mas não expira e funciona em qualquer sistema.

# 1. criar a chave (aperte Enter para aceitar o local padrão)
ssh-keygen -t ed25519 -C "seu-email@exemplo.com"

# 2. mostrar a chave PÚBLICA para copiar
cat ~/.ssh/id_ed25519.pub

# 3. cole em GitHub → Settings → SSH and GPG keys → New SSH key

# 4. testar
ssh -T git@github.com
Hi seu-usuario! You've successfully authenticated...

Com SSH, use os endereços que começam com git@github.com: em vez de https://.

A senha da conta não funciona no terminal

O GitHub não aceita a senha da conta em comandos Git. Se o terminal pedir “Password”, use o login pelo navegador acima ou um personal access token. E nunca coloque tokens ou senhas em arquivos do projeto.
