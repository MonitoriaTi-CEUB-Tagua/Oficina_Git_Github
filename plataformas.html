Teoria Capítulo 8

GitHub, GitLab e outras

O GitHub é o mais famoso, mas não é o único lugar para hospedar repositórios Git. A boa notícia: o Git é igual em todos.

Todas falam Git

Essas plataformas hospedam repositórios Git. Seus commits, branches, merges e todo o fluxo no terminal funcionam do mesmo jeito; só o endereço do remoto muda:

git clone https://github.com/usuario/projeto.git
git clone https://gitlab.com/usuario/projeto.git
git clone https://bitbucket.org/usuario/projeto.git
git clone https://codeberg.org/usuario/projeto.git

O que muda é o que fica em volta do Git: a interface do site, como se faz revisão de código, as automações (CI/CD), a gestão de tarefas, os preços e onde o servidor roda.

Qual escolher?

Estudando e montando portfólio
GitHub. É onde recrutadores olham, onde estão os projetos open source e onde o Student Pack dá benefícios.
Trabalho da faculdade em grupo
A que o professor pedir. Se for livre, GitHub, porque todos provavelmente já têm conta.
Empresa que já usa Jira
Bitbucket costuma vir junto. GitHub e GitLab também se integram ao Jira.
Precisa do código no próprio servidor
GitLab (Community Edition) ou Gitea/Forgejo, mais leves.
Prefere uma opção sem fins lucrativos
Codeberg, para projetos de código aberto.

Usando mais de uma ao mesmo tempo

Como um repositório pode ter vários remotos, nada impede de manter o projeto no GitHub e no GitLab, por exemplo, como backup ou para usar o CI de um com o código do outro.

# o origin já aponta para o GitHub; adicione outro remoto
git remote add gitlab https://gitlab.com/voce/projeto.git
git remote -v

# envie para cada um
git push origin main
git push gitlab main

# baixar de um remoto específico
git fetch gitlab

O Git trata cada remoto separadamente: haverá origin/main e gitlab/main, cada um com sua última posição conhecida.

Migrando de plataforma

Todas oferecem um importador (Import repository ou New project → Import) que traz o histórico completo e, em muitos casos, issues e pull requests. Só com o Git também dá: git clone --mirror do antigo e git push --mirror para o novo.
