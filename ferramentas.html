Ferramentas do dia a dia

Terminal, VS Code ou GitHub Desktop: todos usam o mesmo Git por baixo. Escolha o que for mais confortável e misture quando quiser.

Terminal ou interface gráfica?

Terminal

Funciona igual em qualquer computador e servidor, mostra mensagens completas e tem todos os comandos. Tutoriais e respostas na internet usam o terminal.

Vale aprender, mesmo que você use outra ferramenta no dia a dia.

Interface gráfica

Mostra visualmente o que mudou, facilita escolher linhas para o commit e resolver conflitos. Menos chance de errar o comando.

Cuidado: um clique às vezes roda vários comandos. Saiba o que cada botão faz.

Não precisa escolher um só. O repositório é o mesmo: você pode fazer o commit no VS Code e o push no terminal, por exemplo.

Git no VS Code

O VS Code já vem com Git integrado. Abra a pasta do projeto (File → Open Folder) e clique no ícone de ramificação na barra lateral, ou use Ctrl+Shift+G.

  1. Veja as mudanças. Arquivos alterados aparecem com M (modificado), U (novo, untracked) ou D (apagado). Clique num arquivo para ver o diff lado a lado.
  2. Prepare clicando no + ao lado do arquivo (git add). Para escolher só algumas linhas, selecione-as no diff, clique com o botão direito e escolha Stage Selected Ranges.
  3. Escreva a mensagem na caixa do topo e clique em Commit.
  4. Sincronize. O botão Sync Changes faz pull e depois push. Os números ao lado (↓1 ↑2) mostram quantos commits faltam baixar e enviar.
  5. Troque de branch clicando no nome da branch no canto inferior esquerdo. Ali também dá para criar uma nova.

Também vale conhecer:

  • Conflitos: o VS Code mostra botões Accept Current / Incoming / Both e o Merge Editor de três painéis (veja no capítulo de merge).
  • Timeline (no Explorer, embaixo): histórico de commits do arquivo aberto.
  • Clonar: Ctrl+Shift+P → Git: Clone.

Extensões que ajudam

Git Graph
Desenha o grafo de commits de todas as branches, como os deste guia. Ótimo para entender o que está acontecendo.
GitLens
Mostra quem alterou cada linha e quando (blame), e oferece um histórico rico.
GitHub Pull Requests
Cria, revisa e comenta pull requests sem sair do editor.

GitHub Desktop

Aplicativo oficial do GitHub para Windows e macOS. Bom para quem está começando ou prefere não usar o terminal.

  1. Entre na conta em File → Options → Accounts (no macOS, Settings) e confira nome e e-mail na aba Git.
  2. Pegue um repositório: File → Clone repository (do GitHub), Add local repository (pasta que já é repositório) ou New repository.
  3. Crie uma branch em Current branch → New branch.
  4. Edite no seu editor e volte ao Desktop. Em Changes, marque os arquivos que entram no commit, escreva o Summary e clique em Commit to ….
  5. Envie: Publish branch no primeiro envio, Push origin nos seguintes. Depois, Create Pull Request abre o GitHub no navegador.
  6. Atualize com Fetch origin; se houver novidades, o botão vira Pull origin.

Outras ferramentas

GitHub CLI (gh)
Faz no terminal o que você faria no site: gh repo create, gh pr create, gh pr checkout 12, gh issue list.
github.dev e Codespaces
VS Code no navegador. O github.dev (tecla . no repositório) edita arquivos; o Codespaces cria uma máquina completa na nuvem, com terminal.
IDEs da JetBrains
IntelliJ, PyCharm e WebStorm têm Git integrado, com um ótimo resolvedor de conflitos.
GitKraken, Fork, Sourcetree
Clientes gráficos dedicados, com grafo de branches visual.
lazygit
Interface visual dentro do terminal, controlada pelo teclado.

Atalhos que economizam tempo

Aliases: apelidos para comandos longos

git config --global alias.st status
git config --global alias.sw switch
git config --global alias.lg "log --oneline --graph --all --decorate"

# agora:
git st
git lg

O git lg desenha no terminal um grafo parecido com os deste guia. Use sempre que ficar perdido.

Pequenos truques

  • git switch - volta para a branch anterior.
  • git commit -am "msg" adiciona arquivos já rastreados e faz o commit numa linha só.
  • git log --oneline -5 mostra só os últimos 5 commits.
  • git diff --stat mostra só quais arquivos mudaram e quantas linhas.
  • git show HEAD~1:index.html mostra como o arquivo era um commit atrás.
  • No Git Bash, Tab completa nomes de branches e comandos.
