Problemas e soluções

Deu erro? Copie um pedaço da mensagem e procure abaixo. Cada problema explica por que acontece e como resolver.

Antes de tudo: três comandos de diagnóstico

Quase todo problema fica claro com eles. Rode e leia com calma: o Git costuma dizer o que fazer.

# onde estou, o que mudou, estou à frente ou atrás do GitHub?
git status

# como está o histórico de todas as branches?
git log --oneline --graph --all -15

# para onde estou enviando?
git remote -v

Encontre seu problema

O terminal não reconhece o comando git'git' is not recognized as an internal or external command · git: command not found

Por que acontece

O Git não está instalado, ou o terminal foi aberto antes da instalação e não sabe onde ele está (PATH).

Como resolver

  1. Feche todos os terminais (inclusive o do VS Code) e abra de novo.
  2. Ainda não funciona? Reinstale pelo passo a passo, deixando marcada a opção Git from the command line and also from 3rd-party software.
  3. No Windows, como alternativa, use o Git Bash (procure no menu Iniciar).
O Git pergunta quem é você no commitAuthor identity unknown · *** Please tell me who you are.

Por que acontece

Nome e e-mail nunca foram configurados neste computador.

Como resolver

git config --global user.name "Seu Nome"
git config --global user.email "seu-email@exemplo.com"

Depois, rode o git commit de novo.

Não é um repositório Gitfatal: not a git repository (or any of the parent directories): .git

Por que acontece

Você está numa pasta que não é um repositório. Quase sempre é a pasta errada.

Como resolver

# onde estou?
pwd
# entre na pasta do projeto
cd caminho/do/projeto
# se for um projeto novo, aí sim:
git init

Depois de um git clone, lembre de entrar na pasta criada: cd nome-do-repo.

Pasta aparece com uma seta no GitHub e não abrewarning: adding embedded git repository

Por que acontece

Existe um repositório dentro de outro: uma subpasta tem a sua própria pasta .git (de um git init ou git clone feito dentro do projeto). O Git guarda só uma referência para ela, não os arquivos.

Como resolver

# tira a referência do índice (os arquivos continuam na pasta)
git rm --cached nome-da-subpasta

# apaga o .git de DENTRO da subpasta (confira o caminho!)
rm -rf nome-da-subpasta/.git

# adiciona de novo, agora como arquivos normais
git add nome-da-subpasta
git commit -m "inclui arquivos da subpasta"
Abriu uma tela estranha e não consigo sairPlease enter a commit message… · Merge branch 'main'… (tela do Vim com ~ nas linhas)

Por que acontece

Você rodou git commit sem -m, ou um merge abriu o editor para confirmar a mensagem. O editor padrão é o Vim, que funciona de um jeito diferente.

Como resolver

  1. Aperte Esc.
  2. Digite :wq e Enter para salvar e sair (a mensagem sugerida é usada).
  3. Para cancelar sem salvar: Esc, :q! e Enter.

Para não ver o Vim de novo, use o VS Code como editor:

git config --global core.editor "code --wait"
Aviso sobre LF e CRLFwarning: LF will be replaced by CRLF the next time Git touches it

Por que acontece

Windows e Linux/macOS terminam linhas com caracteres diferentes. O Git está avisando que vai converter automaticamente. Não é erro.

Como resolver

Pode ignorar. Para padronizar, no Windows use git config --global core.autocrlf true. Em equipe, um arquivo .gitattributes com * text=auto resolve para todos.

A senha não funciona no pushremote: Support for password authentication was removed · Authentication failed for 'https://github.com/…'

Por que acontece

O GitHub não aceita a senha da conta em comandos Git.

Como resolver

  • Windows: o Git Credential Manager abre o navegador para login. Se não abrir, reinstale o Git com as opções padrão.
  • Qualquer sistema: instale o GitHub CLI e rode gh auth login.
  • Alternativa: configure uma chave SSH.
  • Se precisar digitar algo em “Password”, use um personal access token (GitHub → Settings → Developer settings), nunca a senha.
Permissão negada com SSHgit@github.com: Permission denied (publickey). fatal: Could not read from remote repository.

Por que acontece

O endereço do remoto usa SSH (git@github.com:…), mas o GitHub não reconhece nenhuma chave deste computador.

Como resolver

# testar a conexão
ssh -T git@github.com

# sem chave? crie uma e cadastre a PÚBLICA no GitHub
ssh-keygen -t ed25519 -C "seu-email@exemplo.com"
cat ~/.ssh/id_ed25519.pub

# ou volte a usar HTTPS
git remote set-url origin https://github.com/usuario/projeto.git
Permissão negada ao repositório (403)remote: Permission to dono/projeto.git denied to voce. · error: 403

Por que acontece

Duas causas comuns:

  1. Você não tem permissão de escrita no repositório: não é colaborador, ou o convite não foi aceito (veja o e-mail ou github.com/notifications).
  2. O computador está logado em outra conta do GitHub (comum em laboratórios).

Como resolver

  • Peça ao dono para adicionar você em Settings → Collaborators, ou faça um fork.
  • Conta errada no Windows: abra Gerenciador de Credenciais → Credenciais do Windows, remova as entradas git:https://github.com e faça o push de novo para logar.
  • No macOS: Acesso às Chaves → procure github.com → apague.

Computador compartilhado

Ao terminar num laboratório, remova suas credenciais do Gerenciador de Credenciais. Senão, a próxima pessoa envia commits com a sua conta.

Push rejeitado! [rejected] main -> main (fetch first) · (non-fast-forward) · Updates were rejected because the remote contains work that you do not have locally

Por que acontece

Alguém enviou commits para a mesma branch depois do seu último pull. O GitHub não deixa você sobrescrever o trabalho dessa pessoa.

Como resolver

git pull
# se der conflito, resolva (veja abaixo), depois:
git push

Não use git push --force: ele apagaria o commit do colega.

O pull pede para escolher como juntarhint: You have divergent branches and need to specify how to reconcile them. · fatal: Need to specify how to reconcile divergent branches.

Por que acontece

Você e o GitHub têm commits diferentes, e o Git quer saber se junta com merge ou com rebase.

Como resolver

# escolha uma vez (merge é o comportamento clássico)
git config --global pull.rebase false
git pull

Prefere histórico linear? Use git config --global pull.rebase true. As diferenças estão em Remotos.

A branch não tem upstreamfatal: The current branch feature has no upstream branch.

Por que acontece

É o primeiro push dessa branch, e o Git não sabe para onde enviar.

Como resolver

Use o comando que o próprio Git sugere:

git push -u origin nome-da-branch

Nos próximos, basta git push. Para o Git fazer isso sozinho sempre: git config --global push.autoSetupRemote true.

Push falha com src refspecerror: src refspec main does not match any

Por que acontece

Não existe branch local com esse nome. Ou você ainda não fez nenhum commit, ou a branch se chama master.

Como resolver

# tem commit?
git log --oneline
# qual o nome da branch?
git branch

# sem commit: faça o primeiro
git add .
git commit -m "primeiro commit"

# se chama master: renomeie
git branch -M main
git push -u origin main
O remoto origin já existeerror: remote origin already exists.

Por que acontece

O repositório já tem um origin (talvez você clonou, ou já rodou o remote add antes).

Como resolver

# ver para onde aponta
git remote -v
# trocar o endereço
git remote set-url origin https://github.com/usuario/novo-repo.git
Históricos sem relaçãofatal: refusing to merge unrelated histories

Por que acontece

Você criou o repositório no GitHub com README e também criou um repositório local com git init. São dois históricos que começaram separados.

Como resolver

git pull origin main --allow-unrelated-histories
# resolva conflitos se aparecerem (geralmente no README), depois:
git push -u origin main

Para evitar: ou comece pelo GitHub e clone, ou crie o repositório no GitHub vazio.

Arquivo grande demais para o GitHubremote: error: File video.mp4 is 142.00 MB; this exceeds GitHub's file size limit of 100.00 MB

Por que acontece

O GitHub recusa arquivos acima de 100 MB. Como o arquivo está em um commit, apagá-lo agora não basta: ele continua no histórico.

Como resolver

Se o arquivo entrou no último commit e ainda não foi enviado:

git rm --cached video.mp4
echo "video.mp4" >> .gitignore
git add .gitignore
git commit --amend --no-edit
git push

Se entrou em commits mais antigos, desfaça os commits locais que ainda não foram enviados (git reset --soft origin/main), tire o arquivo e faça um commit novo. Para arquivos grandes que precisam ser versionados, use o Git LFS.

Alterações locais seriam sobrescritaserror: Your local changes to the following files would be overwritten by checkout/merge. Please commit your changes or stash them.

Por que acontece

Você tem arquivos editados sem commit e o comando (switch, pull, merge) precisaria substituí-los.

Como resolver

# opção 1: faça commit
git add .
git commit -m "trabalho em andamento"

# opção 2: guarde na gaveta, rode o comando, devolva
git stash
git pull
git stash pop

# opção 3: descarte as alterações (cuidado: perde o trabalho)
git restore .
HEAD solto (detached HEAD)You are in 'detached HEAD' state. · HEAD detached at 3f9a2c1

Por que acontece

Você fez checkout de um commit (ou de uma tag) em vez de uma branch. Dá para olhar à vontade, mas commits feitos aqui ficam sem branch.

Como resolver

# só estava olhando? volte
git switch main

# fez commits e quer guardar? crie uma branch AQUI
git switch -c minha-branch

Já saiu e perdeu os commits? Veja recuperar commits perdidos.

Fiz commit na branch erradaFiz o commit na main, mas devia estar numa branch

Como resolver (antes do push)

# 1. crie a branch apontando para onde você está (guarda o commit)
git branch feature/nova-tela
# 2. volte a main um commit
git reset --hard HEAD~1
# 3. continue na branch certa
git switch feature/nova-tela

Se o commit era para uma branch que já existe: git switch branch-certa, git cherry-pick HASH, e depois volte à branch errada para tirar o commit com git reset --hard HEAD~1.

Perdi commits (reset, branch apagada, detached HEAD)Meus commits sumiram do git log

Por que acontece

Commits sem nenhuma branch apontando não aparecem no git log, mas continuam no repositório por algumas semanas. O reflog registra todo lugar por onde o HEAD passou.

Como resolver

git reflog
a1b2c3d HEAD@{0}: reset: moving to HEAD~1
9f8e7d6 HEAD@{1}: commit: tela de login   <- era esse!
4e5f6a7 HEAD@{2}: checkout: moving from main to feature

# crie uma branch no commit perdido
git branch resgate 9f8e7d6
A branch do colega não apareceerror: pathspec 'feature/x' did not match any file(s) known to git · fatal: invalid reference

Por que acontece

Seu Git ainda não sabe que a branch existe no GitHub.

Como resolver

git fetch
git branch -a          # deve aparecer remotes/origin/feature/x
git switch feature/x   # cria a local ligada à remota
Conflito de mergeCONFLICT (content): Merge conflict in index.html · Automatic merge failed; fix conflicts and then commit the result.

Por que acontece

As duas versões mudaram as mesmas linhas. O Git precisa que você escolha o resultado.

Como resolver

  1. git status mostra os arquivos em both modified.
  2. Abra cada um, procure <<<<<<<, deixe a versão final e apague as marcações (<<<<<<<, =======, >>>>>>>). No VS Code, use os botões Accept….
  3. Teste o projeto.
  4. git add arquivo e git commit.

Quer desistir? git merge --abort. Passo a passo completo em Merge e conflitos.

Conflito durante rebase ou pull --rebaseCONFLICT … could not apply 9f8e7d6… · interactive rebase in progress

Como resolver

# resolva os arquivos, então:
git add arquivo
git rebase --continue
# pode parar de novo no próximo commit; repita

# ou desista e volte ao estado anterior
git rebase --abort

No rebase, “current” e “incoming” se invertem: HEAD é a branch de destino e o “incoming” é o seu commit sendo reaplicado.

Commitei o arquivo com as marcações de conflito<<<<<<< HEAD aparecendo no site ou no código

Como resolver

Sem pânico: é só um arquivo com texto errado. Edite, remova as marcações, deixe a versão correta e faça um commit novo:

# procurar marcações esquecidas no projeto
git grep -n "<<<<<<<"
# depois de corrigir
git add .
git commit -m "remove marcações de conflito"

Ainda não fez push

git commit --amend -m "mensagem correta"

Já fez push

Deixe como está. Alterar exigiria push --force, o que atrapalha quem já baixou. Uma mensagem imperfeita não faz mal.

Esqueci um arquivo no último commitO commit foi sem um arquivo que devia ir junto 
git add arquivo-esquecido.css
git commit --amend --no-edit

Só antes do push. Depois do push, faça um commit novo normal.

Quero desfazer o último commit (não enviado)Fiz commit cedo demais / commitei o que não devia 
# desfaz o commit, mantém as mudanças preparadas (staged)
git reset --soft HEAD~1

# desfaz o commit, mantém as mudanças na pasta (fora do stage)
git reset HEAD~1

# desfaz o commit E joga fora as mudanças
git reset --hard HEAD~1

HEAD~1 é “um commit antes do atual”; HEAD~3 volta três.

Quero desfazer um commit que já foi enviadoO commit com problema já está no GitHub 
git log --oneline        # ache o hash do commit
git revert 9f8e7d6       # cria um commit que desfaz aquele
git push

O revert não reescreve o histórico, então ninguém da equipe é prejudicado. Para desfazer um commit de merge: git revert -m 1 HASH.

Commitei uma senha, token ou arquivo .envSegredo exposto no repositório · GitHub push protection: secret detected

Primeiro: troque o segredo

Se foi enviado ao GitHub, considere que vazou, mesmo em repositório privado e mesmo se você apagar depois. Gere uma senha ou chave nova no serviço e desative a antiga. Só depois limpe o repositório.

Ainda não fez push

git rm --cached .env
echo ".env" >> .gitignore
git add .gitignore
git commit --amend --no-edit

Já fez push

Remova o arquivo num commit novo e adicione ao .gitignore. Apagar do histórico inteiro exige ferramentas como git filter-repo e um push forçado; peça ajuda aos monitores.

Se o GitHub bloqueou o push (push protection), ele já evitou o vazamento: tire o segredo do commit (amend ou reset) e envie de novo.

Coloquei no .gitignore, mas o arquivo continua aparecendo.gitignore não funciona · node_modules continua no git status

Por que acontece

O .gitignore só vale para arquivos que ainda não são rastreados. Se o arquivo já entrou num commit, o Git continua acompanhando.

Como resolver

# para de rastrear (o arquivo continua no seu computador)
git rm --cached arquivo
git rm -r --cached node_modules/

git commit -m "para de versionar arquivos ignorados"
Quero descartar tudo e voltar ao último commitBaguncei tudo, quero começar de novo 
# descarta mudanças em arquivos rastreados
git restore .

# mostra arquivos novos que seriam apagados (simulação)
git clean -n
# apaga de verdade arquivos e pastas não rastreados
git clean -fd

# deixar igualzinho ao GitHub (perde commits locais não enviados!)
git fetch
git reset --hard origin/main

Tudo isso é irreversível para mudanças sem commit. Na dúvida, rode antes git stash -u, que guarda tudo numa gaveta.
