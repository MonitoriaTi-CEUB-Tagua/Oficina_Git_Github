Git e GitHub não são a mesma coisa

É a confusão mais comum de quem começa. Vale fixar desde já:

Git

Um programa que roda no seu computador e registra o histórico de uma pasta. Funciona sem internet.

Criado em 2005 por Linus Torvalds para organizar o desenvolvimento do Linux. É gratuito e de código aberto.

≠

GitHub

Um site que guarda cópias de repositórios Git na nuvem e adiciona ferramentas de equipe: pull requests, issues, revisão de código, automações.

Não é o único: GitLab, Bitbucket e outros fazem o mesmo papel.

Analogia

O Git é a câmera que tira fotos do seu projeto. O GitHub é o álbum compartilhado na nuvem, onde a turma toda vê, comenta e junta as fotos.

Como ler os grafos deste guia

Todos os desenhos de histórico seguem as mesmas regras. Os grafos interativos rodam comandos Git de verdade num simulador, então o que você vê é o que o Git faria.

Bolinha cheia com letra
Um commit. Nos grafos usamos letras (A, B, C) no lugar do hash real, que seria algo como 3f9a2c1.
Cor da linha
Cada branch tem uma cor. A main é sempre a linha de cima.
Bolinha vazada
Commit de merge: ele tem dois pais, um de cada caminho.
Etiqueta colorida
Uma branch apontando para aquele commit. O ☁ indica que o GitHub está na mesma posição.
HEAD
“Você está aqui”: a branch em que você está trabalhando agora.
Contorno tracejado
Commit que existe no GitHub mas ainda não foi baixado para o seu computador. A etiqueta origin/main mostra a última posição conhecida do GitHub.
Bolinha apagada
Commit que ficou sem nenhuma branch apontando (depois de um reset ou rebase, por exemplo). Ainda dá para recuperá-lo por um tempo.
