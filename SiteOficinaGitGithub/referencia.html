Mensagens frequentes

“Not a git repository”

O terminal está fora da pasta do repositório. Entre na pasta correta com cd e rode git status. Só use init se quiser realmente criar um novo repositório.

“Nothing to commit”

Não há mudanças preparadas para registrar. Confira se salvou o arquivo, se está na pasta certa e se ele está ignorado. Arquivos só modificados precisam de git add antes do commit.

Push rejeitado: “non-fast-forward”

Há histórico remoto que sua branch não contém. Rode git fetch origin, inspecione os commits e integre as mudanças da branch remota correspondente. Por exemplo, na main: git merge origin/main. Resolva conflitos e teste antes de enviar. Não use force como correção automática.

“Authentication failed” ou “Permission denied (publickey)”

Confira a URL com git remote -v e a conta com permissão no projeto. Em HTTPS, use o gerenciador de credenciais ou token adequado. Em SSH, confira a chave pública cadastrada e sua configuração de chave privada.

“Your local changes would be overwritten”

Existem edições que seriam sobrescritas pela operação. Faça commit ou guarde-as com stash, depois tente novamente. Só descarte se tiver certeza de que não precisa delas.

O site publicado aparece sem CSS ou retorna 404

Confira a fonte do Pages, o nome exato index.html e as maiúsculas/minúsculas dos caminhos. Sites de projeto usam uma subpasta; por isso este guia usa assets/css/style.css, sem uma barra inicial. Consulte também o resultado da publicação na aba Actions.

Desfazer sem confundir as operações

SituaçãoOpção
Preparei o arquivo erradogit restore --staged ARQUIVO; mantém a edição.
Quero descartar edição ainda não preparadagit restore ARQUIVO; descarta essa edição.
Preciso desfazer um commit já compartilhadogit revert HASH; cria um novo commit de reversão. Pode gerar conflitos.
Preciso trocar de tarefa sem concluir o trabalhogit stash push -u e depois git stash pop. O stash é local, não backup remoto.

Reverter um merge é um caso especial e exige identificar o pai principal; o exemplo simples de revert não cobre esse cenário.

Prática: publique uma melhoria

Use um repositório de treino com este guia. O objetivo é alterar o README usando uma branch e integrar por PR.

  1. Clone o repositório e crie docs/apresentacao.
  2. Adicione ao README uma seção explicando o que você aprendeu.
  3. Confira o diff, faça um commit e publique a branch.
  4. Abra um PR, revise os arquivos alterados e escreva como verificou a mudança.
  5. Faça o merge, volte à main local e atualize.
  6. Confira o histórico e a versão final no GitHub.
terminal
git clone https://github.com/SEU-USUARIO/guia-git-ceub.git
cd guia-git-ceub
git switch -c docs/apresentacao
# Edite e salve README.md
git diff
git add README.md
git commit -m "docs: registra aprendizado sobre Git"
git push -u origin docs/apresentacao

Depois de concluir o PR no GitHub:

terminal
git switch main
git pull --ff-only
git log --oneline -5

Checklist de estudo; as marcações não são salvas ao recarregar.
