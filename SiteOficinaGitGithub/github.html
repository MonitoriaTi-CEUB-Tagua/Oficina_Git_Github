GitHub: organize e publique

Use o repositório como ponto de encontro do projeto: código, tarefas, revisão, documentação e publicação.

O que cada área oferece

ÁreaPara que usar
CodeNavegar pelos arquivos, branches, commits e README. O botão Code mostra URLs de clone.
IssuesRegistrar bugs, tarefas e propostas; atribuir responsáveis, labels e marcos.
Pull requestsRevisar e integrar alterações entre branches ou forks.
ActionsExecutar automações, testes e publicação configurados em workflows. Confira logs quando uma verificação falhar.
ProjectsOrganizar issues e PRs em tabelas, quadros e outras visualizações de planejamento.
DiscussionsConversas abertas, perguntas e decisões, quando habilitadas.
Releases / TagsMarcar versões e distribuir notas e arquivos de uma entrega. Uma tag identifica um ponto do histórico; uma release adiciona apresentação e anexos.
SettingsConfigurar colaboradores, regras de branches, secrets e Pages. A disponibilidade depende da sua permissão e do plano.

Issues que ajudam a resolver

Uma issue descreve trabalho ou um problema; o PR contém uma proposta de mudança no código. Antes de criar uma issue, pesquise se ela já existe.

modelo de issue
## Problema
O menu fica fora da tela em celulares.

## Como reproduzir
1. Abra a pagina inicial.
2. Use uma janela com 360 px de largura.
3. Abra o menu.

## Resultado esperado
Os links devem caber na tela e continuar acessiveis.

## Resultado observado
O ultimo link fica cortado.

## Ambiente
Informe navegador, sistema e versao testados.

## Evidencias
Anexe uma captura sem dados privados.

Use labels para categoria, assignees para responsáveis e milestones para uma entrega. Uma checklist pode dividir a tarefa. Não publique dados pessoais, tokens ou senhas nos exemplos.

Combine regras simples para a equipe

  • Uma tarefa por branch e PRs pequenos, com contexto e testes.
  • Revisar o diff antes do envio; discutir a solução, não a pessoa.
  • Proteger a main com revisão e verificações quando disponíveis.
  • Usar CONTRIBUTING.md para orientar contribuições e templates em .github/ para padronizar issues e PRs.
  • Registrar como executar o projeto e quais configurações são necessárias.
Permissões importam: clonar um repositório público não permite enviar mudanças para ele. É preciso acesso de escrita ou o fluxo de fork + PR.

Publique este guia no GitHub Pages

GitHub Pages hospeda sites estáticos: HTML, CSS e JavaScript executado no navegador. Este guia foi preparado para isso, sem backend ou instalação de dependências.

  1. Extraia o ZIP. Abra a pasta guia-git-ceub; o arquivo index.html deve ficar na raiz do repositório, não dentro de uma pasta extra.
  2. Crie um repositório público, por exemplo guia-git-ceub, e envie os arquivos extraídos por Git ou Desktop. Inclua o arquivo .nojekyll.
  3. No repositório, abra Settings → Pages.
  4. Em Build and deployment → Source, selecione Deploy from a branch.
  5. Selecione a branch main, pasta /(root), e clique em Save.
  6. Acompanhe a publicação e abra o endereço mostrado pelo GitHub. Em um site de projeto, normalmente será https://SEU-USUARIO.github.io/guia-git-ceub/.

Depois, novos pushes na fonte selecionada atualizam a publicação. Repositórios privados dependem do plano; a visibilidade do repositório não deve ser confundida com controle de acesso ao site.

Como editar este material

Os HTML já estão prontos. Para uma alteração pontual, você pode editá-los diretamente. Para manutenção consistente de várias páginas, edite os arquivos-fonte e regenere:

Arquivo / pastaResponsabilidade
content/*.htmlConteúdo de cada capítulo.
templates/page.htmlLayout comum, cabeçalho, navegação e rodapé.
content/pages.jsonTítulos, descrições, ordem e referências dos capítulos.
assets/css/style.cssIdentidade visual e responsividade.
assets/js/main.jsMenu mobile, copiar, busca e demonstração de branches.
scripts/build.pyGera os HTML estáticos a partir das fontes.
terminal — na raiz do projeto
python scripts/build.py

Python 3 só é necessário para regenerar. O site publicado não depende de Python. Alterações feitas diretamente nos HTML gerados serão substituídas na próxima geração; prefira editar os arquivos de content/.
