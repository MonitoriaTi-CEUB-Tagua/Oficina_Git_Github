Repositórios, clone e fork

Escolha entre começar um projeto, baixar uma cópia de trabalho ou contribuir em um projeto de outra pessoa.

Clone, fork ou Download ZIP?

Operação Resultado Quando usar
git clone Cópia local com histórico Git e remoto configurado. Desenvolver no computador. Não concede permissão para enviar ao original.
Fork Repositório na sua conta do GitHub vinculado ao projeto original. Propor mudanças sem acesso de escrita ao original. Depois, clone seu fork.
Download ZIP Arquivos de uma versão, sem a pasta .git. Apenas ler ou executar. Não substitui um clone para contribuir.

Clonar um projeto existente

No repositório, abra Code → Local → HTTPS e copie a URL. No terminal, vá até a pasta onde quer guardar seus projetos.

terminal
git clone https://github.com/SEU-USUARIO/meu-projeto.git
cd meu-projeto
git status
git remote -v

O clone cria a pasta meu-projeto. O nome origin normalmente representa a URL de onde você clonou. Você não precisa rodar git init depois de clonar.

Criar um projeto do zero

No GitHub, use New repository, escolha o nome e a visibilidade. Para acompanhar este exemplo, crie um repositório vazio, sem README, licença ou .gitignore.

terminal
mkdir meu-projeto
cd meu-projeto
git init -b main
echo "# Meu projeto" > README.md
git add README.md
git commit -m "docs: cria README inicial"
git remote add origin https://github.com/SEU-USUARIO/meu-projeto.git
git push -u origin main

-u associa sua branch local à remota para os próximos push e pull. Se o repositório no GitHub já tiver arquivos, prefira cloná-lo e adicionar seu trabalho nessa cópia.

Contribuir usando fork

  1. No projeto original, clique em Fork → Create fork.
  2. Clone o fork da sua conta.
  3. Adicione o original como upstream; esse nome é uma convenção, não uma palavra especial do Git.
  4. Crie uma branch, faça commits e envie para origin, seu fork.
  5. No GitHub, abra um pull request com destino ao repositório original.
terminal
git clone https://github.com/SEU-USUARIO/projeto.git
cd projeto
git remote add upstream https://github.com/AUTOR-ORIGINAL/projeto.git
git switch -c docs/melhora-guia
# Edite e salve README.md antes dos próximos comandos
git add README.md
git commit -m "docs: esclarece instalacao"
git push -u origin docs/melhora-guia

Manter o fork atualizado

Com sua main sem mudanças próprias e a área de trabalho limpa:

terminal
git switch main
git fetch upstream
git merge --ff-only upstream/main
git push origin main

Se --ff-only recusar, os históricos divergiram. Revise os commits antes de decidir como integrar; não force o envio. Confira também se o projeto original usa main ou outro nome de branch.
