Commits e sincronização

Registre mudanças com intenção, confira o que está enviando e mantenha o trabalho atualizado.

O ciclo de trabalhoEscreva mensagens úteisFetch, pull e pushLeia o históricoEvite versionar arquivos desnecessários

O ciclo de trabalho

Exemplo: você editou index.html e quer registrar apenas essa alteração.

terminal
git status
git diff
git add index.html
git diff --staged
git commit -m "feat: adiciona pagina inicial"
git push
Comando O que observar
status Branch atual, arquivos novos, modificados e preparados.
diff Diferenças ainda não colocadas no stage.
add index.html Seleciona a versão atual do arquivo. Se editar novamente, rode add de novo para incluir as novas mudanças.
diff --staged O conteúdo exato que entrará no próximo commit.
commit Cria um registro local. Inclua uma mudança coerente por commit.
push Envia commits. Na primeira publicação da branch, use git push -u origin NOME-DA-BRANCH.
git add . seleciona alterações no diretório atual e abaixo dele, incluindo novos arquivos e remoções. Confira sempre o stage para não incluir algo por engano.

Escreva mensagens úteis

Prefira uma ação concreta: “corrige validação de e-mail” informa mais que “arruma coisas”. Prefixos são convenções da equipe, não exigências do Git.

Prefixo comum Exemplo
feat: feat: adiciona filtro por categoria
fix: fix: corrige envio duplicado
docs: docs: explica configuracao local
refactor: refactor: separa validacao do formulario
test: test: cobre cadastro com email invalido
chore: chore: atualiza configuracao do editor

Fetch, pull e push

Comando Efeito
git fetch origin Busca dados do remoto e atualiza referências como origin/main; não integra automaticamente na sua branch.
git pull --ff-only Busca e atualiza a branch local apenas se puder avançar sem criar um merge. Recusa históricos divergentes.
git push Envia commits locais para o remoto. Não envia edições sem commit.

Um git pull sem opções busca e integra segundo as opções/configurações do Git, podendo usar merge ou rebase. Neste guia, usamos --ff-only para tornar a atualização explícita e previsível.

Leia o histórico

terminal
git log --oneline --graph --all --decorate
git show HEAD
git remote -v

HEAD indica sua posição atual no histórico. Normalmente aponta para uma branch. origin/main é sua referência local da main remota, atualizada na última comunicação apropriada com o remoto.

Evite versionar arquivos desnecessários

Crie .gitignore na raiz, ajustado à tecnologia do projeto:

.gitignore
# Dependencias e arquivos gerados
node_modules/
build/
dist/

# Configuracao privada
.env
.env.*
!.env.example

# Sistema operacional
.DS_Store
Thumbs.db

Esse é um exemplo para projetos que geram dist/. Neste site, os HTML publicados são versionados na raiz. Não ignore arquivos necessários à publicação.

Já está rastreado? Adicionar ao .gitignore não remove o arquivo do histórico. git rm --cached ARQUIVO deixa de rastreá-lo no próximo commit e mantém a cópia local. Se publicou uma credencial, revogue-a; apagar o arquivo não elimina versões anteriores.
