Branches: trabalho em paralelo

A branch dá um nome a uma linha de desenvolvimento. Você pode experimentar sem alterar imediatamente a versão principal.

Uma branch não é outra pasta

Uma branch é uma referência que aponta para um commit. Ao criar outra, você cria um novo ponto de acompanhamento do histórico. Ao trocar de branch, o Git ajusta os arquivos da sua pasta à versão selecionada.

Antes de trocar: veja git status. Edições sem commit podem acompanhar você para outra branch ou impedir a troca. Faça commit ou use stash quando precisar guardar trabalho incompleto.

Crie e publique sua branch

terminal
git switch main
git pull --ff-only
git switch -c feature/menu
# Edite e salve index.html
git add index.html
git commit -m "feat: adiciona menu de navegacao"
git push -u origin feature/menu

switch -c cria e já entra na branch. Para entrar em uma branch local existente, use git switch feature/menu. O primeiro push publica a branch no GitHub.

Veja o que muda a cada etapa

main

O projeto começa no commit A. HEAD aponta para main, a branch atual.

main: A • HEAD → main

terminal
git status

Demonstração local: nenhum comando é executado no seu computador.

Organize as branches

Use nomes curtos e descritivos, sem espaços. Prefixos ajudam a identificar a finalidade; combine o padrão com a equipe.

Nome Finalidade
main Versão principal, idealmente sempre utilizável.
feature/cadastro Nova funcionalidade.
fix/menu-mobile Correção de um problema.
docs/guia-instalacao Documentação.

Não é obrigatório criar develop ou adotar Git Flow. Em projetos pequenos, branches curtas saindo de main e voltando por pull request costumam ser suficientes.

Listar, acompanhar e limpar

referência — execute conforme a necessidade
git branch
git branch -a
git fetch origin
git switch --track origin/feature/menu

O último comando serve quando a branch existe no remoto e ainda não existe localmente com esse nome. Após integrar e atualizar main:

terminal
git switch main
git pull --ff-only
git branch -d feature/menu

-d verifica se é seguro remover a referência local conforme os critérios do Git. Após squash merge, pode recusar porque os commits originais não aparecem como integrados; confirme o conteúdo antes de qualquer exclusão forçada. A branch remota pode ser removida pelo botão Delete branch do pull request.
